# Hard Rerank Benchmark v1

На 24 положительных запросах Voyage Rerank улучшил nDCG@10 в **11 случаях**, не изменил в **11** и ухудшил в **2**. Средний nDCG@10 вырос с **0.94235 до 0.97502** (+0.03268). При этом существующий semantic search уже давал содержательно релевантный top-1 в **23/24** случаях; после rerank — **24/24**. Польза здесь чаще состоит в перестановке дополнительных источников, чем в исправлении первого ответа.

Выполнены **28 настоящих Rerank-вызовов** и **2 настоящих embedding-вызова**. Общая подтверждённая стоимость — **$0.00243830** из разрешённых $0.03; неопределённых начислений в конце нет. Средняя добавленная задержка Rerank — **675.5 мс**, медиана **516 мс**, p95 **1042 мс**. Полный очищенный набор результатов, receipts, candidate pools, фрагменты и исходные semantic scores: [JSON](rerank-hard-benchmark-v1.json).

## Что именно проверено

Индекс построен цепочкой `MarkdownChunker → IndexingService → LocalVectorStore → SemanticSearchService` на реальных embeddings OpenRouter. Embedding-провайдер использует production serializer и validator; два пакета содержат 64 и 44 входа. Тексты запросов включены в эти пакеты один раз, затем production search читает соответствующие сохранённые реальные векторы. Это не искусственные embeddings. Повторных embedding-запросов ради сравнения нет.

Для каждого вопроса production search вернул **30 документов в собственном порядке**, с максимум тремя chunk matches на документ. `prepareRerankCandidates` выбрал один актуальный фрагмент на заметку с проверкой content hash/provenance. Все 30 кандидатов во всех 28 случаях прошли подготовку и ограничения payload. Ничего не добавлялось в пул по разметке и не заменялось более удобным текстом.

Уточнение выполнялось через production `refinedSearch`, поверх сохранённого пула, и установленный `OpenRouterRerankProvider` в отдельном временном Obsidian. Транспорт — **настоящий `requestUrl`**, endpoint — **POST `https://openrouter.ai/api/v1/rerank`**, `provider.allow_fallbacks=false`, модель только `voyageai/rerank-3-lite`. Проверялись точный SHA тела до отправки, индексы, конечные scores, production validator, отдельный rerank score и сохранение semantic score. **28/28 HTTP 200 и validator PASS**. Resolved model: `rerank-3-lite`, provider: `VoyageAI by MongoDB`.

Исправление #72 сохранено: во всех исходящих фрагментах отсутствуют `note-NNN` из filename fallback. Настоящие заголовки присутствуют. Enriched-представление для индекса сохранено как в production. Ключ передавался native-процессу только в память; сохранённый `data.json` проверен на отсутствие ключа. Личный vault и постоянный профиль не использовались.

**Новый native UI smoke — NOT RUN.** Здесь проверен native production-адаптер, а не повторное открытие результатов и переход к фрагменту через UI. Эти действия исторически проверены в [#73](https://github.com/zinverno/veynrel/pull/73) и не выдаются за новое наблюдение.

## Разметка и метрики

Разметка агентская, без независимой экспертной оценки. До любых model outcomes явно оценены все **1 792 пары** «вопрос–документ». Ненулевые оценки содержат обоснование и заранее выбранный маркер ответного passage; остальные пары имеют 0. [Manifest](../tests/fixtures/rerank-hard-v1/manifest.json) фиксирует неоднозначности; [полная матрица](../tests/fixtures/rerank-hard-v1/judgments.json) позволяет их проверить.

Оценки: 0 — нерелевантно; 1 — слабая/косвенная польза; 2 — содержательный, но неполный ответ; 3 — прямой полноценный ответ. Для Hit/MRR/Recall релевантность означает **grade ≥2**. nDCG использует gain `2^grade − 1`; идеальный порядок берётся по всем 64 документам. Итоговый `k=10` одинаков до и после. MRR@10 равен нулю, если релевантного документа нет в top-10. Recall@30 измеряет исходный retrieval относительно всех заранее размеченных документов grade ≥2.

Основной критерий Improved/Unchanged/Regressed — изменение nDCG@10 с допуском **1e-9**. «Unchanged» означает равную метрику, а не обязательно идентичный порядок документов одного grade. Четыре вопроса без ответа исключены из положительных агрегатов; их nDCG — null. Порог отказа по score не выводится.

| Метрика, 24 положительных запроса | Semantic baseline | После Rerank |
|---|---:|---:|
| Hit@1 | 23/24 (95.83%) | 24/24 (100%) |
| Hit@3 | 24/24 (100%) | 24/24 (100%) |
| MRR@10 | 0.97917 | 1.00000 |

Grade-3 документ был первым в **21/24** baseline и **22/24** после. Остались случаи D1 и E3, где grade-2 источник стоит выше grade-3. Это не противоречит Hit@1=100% при пороге grade ≥2.

Из 11 улучшений **шесть** (A1, C1, C4, F1, F2, F3) меняют позиции только grade-1 материалов: позиции содержательно релевантных документов в top-10 не улучшились. Улучшения их позиций наблюдались в **пяти** кейсах: A3, A4, B1, C3, E2. Только A3 изменил первый релевантный ответ с позиции 2 на 1.

## Наблюдаемые случаи

**Наибольшее улучшение — A3.** «The machine lost power halfway through an overnight conversion. How do we continue from work already safely finished?» `note-007.md` (grade 3) поднялся **2→1**, `note-055.md` (grade 1) — **11→6**; nDCG **0.57876→0.96400**. На первом месте baseline стоял `note-045.md`, выбранный раздел `Planned maintenance`: он описывает остановку сервиса и сохранение идентификаторов незавершённой работы, но не проверяемую границу уже выполненной конвертации. `note-007.md` описывает durable outputs и проверяемый checkpoint. Видно исправление выбора первого документа; внутреннюю причину решения модели из этих данных установить нельзя.

**Наибольшее ухудшение — A2.** «I recognize a foreign expression on the page but cannot bring it to mind when speaking. What practice changes that?» Главный ответ `note-004.md` (grade 3) остался **1→1**, но полезная интегрированная практика `note-044.md` (grade 2) упала **4→8**. nDCG **0.91486→0.88720**. После Rerank в top-3 стоят заметки о перечитывании и различении звуков, размеченные для этого вопроса grade 0; первая из них поднялась 6→2, вторая осталась третьей. Нужный passage `note-044` присутствовал в отправленном фрагменте: это не потеря текста при chunk selection.

**Вторая регрессия — E1.** «Which checks establish that an encrypted backup can actually restore the expected files after losing the working machine?» Прямой ответ с проверкой ключа и восстановления `note-038.md` остался **1→1**. Rehearsal `note-039.md` (grade 2) опустился **2→3**, а заметка об изоляции backup `note-040.md` (grade 1) поднялась **3→2**. nDCG **0.98558→0.96576**. Оба текста были доступны модели; разница grade заранее отражала отличие реальной проверки восстановления от защиты копии.

**Успех без дополнительной пользы — B2.** «How can I query a live SQLite database without a long lock blocking writers and without making a file copy for every read?» `note-014.md` с WAL уже был первым и остался первым; nDCG **1→1**, задержка **505 мс**, стоимость **$0.00007662**. Во всех 11 неизменных положительных кейсах потрачено **$0.00088990** без прироста основной метрики. Две регрессии добавили **$0.00015122**.

**Выбор одного фрагмента длинной заметки — F1–F4.** Наблюдаемого пропуска ответного фрагмента здесь **нет**. Для F1 вопрос о проснувшемся старом владельце lease выбрал `note-045.md`, раздел `Publication barrier`, chunk ordinal 3 (четвёртый), source offsets **1481–2261**, строки **16–18 в нумерации production source**. В payload попал ресурсный fencing, а не первые разделы о deployment/leases. Документ остался **1→1**; прирост nDCG связан только с grade-1 источником `note-053.md` (**8→3**). Для F2–F4 также выбран четвёртый чанк, с заранее указанным ответным маркером, и главный документ остался первым. Остальные четыре чанка каждой длинной заметки Rerank не видел. Это подтверждает успешный выбор позднего фрагмента в этих примерах, но не проверяет случай, когда важные части ответа распределены по нескольким чанкам. Приписывать модели ошибку chunk selection по этому прогону нельзя.
